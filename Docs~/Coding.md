# 🚧 施工場

> 一句話：**改既有的程式碼之前先進場、宣告施工範圍；範圍跟別人重疊就開 worktree，不要擠在同一個工作區。**
> 參數表、範圍怎麼判重疊、自動收場的五種「不收」看 `senate cmd help coding`。⛔ 本檔不重抄。

## 1. 什麼時候要進場

| 情形 | 進場？ |
|---|---|
| 改動既有的程式碼 —— 任何語言、任何專案（C#、JS、Python、shader…） | ✅ 要 |
| 新檔要接進既有的檔（註冊、import、清單、設定檔） | ✅ 要 —— 那就是改了既有的檔 |
| 跑會重寫建置產物的指令（build、import／reimport 結尾自動 build、publish） | ✅ 要 —— 見 §3 |
| 只新增檔案，沒動到任何既有的檔 | ❌ 不用（新檔沒有人會跟你撞） |
| 只改文件、信件、記憶、資料 | ❌ 不用（那些有各自的寫入端） |

- 只有 FreeTime／StreamWatch 場的人，要動程式碼也得**另開** Coding 場 —— 別的場不會替你擋撞車。
- 「先改一點點再說」是最常見的漏洞：改第一行之前就進場。

## 2. 進場：宣告施工範圍

```bash
# 有單：認領時帶範圍 ⇒ 認領＋開場＋綁單一次做完（開不了場就不認領）
senate cmd task --arg op=claim --arg persona=<我> --arg index=<N> --arg scope="<路徑>|<路徑>"
# 沒有單：直接開場
senate cmd coding --arg op=start --arg persona=<我> --arg status="<在改什麼>" --arg scope="<路徑>|<路徑>"
```

- ⛔ 認領不帶 `scope` **不會開場**，只是「記錄我在做這件事」。
- 範圍取**最大**：會改的每支檔、會被你重寫的產物都列進去。宣告得比實際窄，擋不住真正會撞的人，而且不會叫。
- 不知道會碰到哪裡 ⇒ 宣告整個目錄（寬一點只是讓別人多等，窄了是撞車）。

## 3. 建置產物也是施工範圍

有些產物會把**整個來源**一起建進去（單檔成品、打包檔、self-contained exe）。

- 在共用工作區 build ＝ 把**別人還沒提交的半成品**一起包進去。兩個人改的來源不重疊，閘照樣放行，而那份產物是混合版。
- ⇒ **要 build 的人，scope 一律含那份產物**（例：遊戲的 `index.html`、Senate 的 `publish/`）。這樣 build 的人彼此互斥。
- 交出去給人測的版本，要說得出是從哪一版建的：提交過的才乾淨。

🩸 2026-10-16：有人在共用工作區建了遊戲成品，包進另一個人改到一半的 js ⇒ 開砲後整場停住，Tim 以為是卡死。當時建成品的人只有 FreeTime 場，這道閘根本沒機會叫。

## 4. 進不了場 ⇒ 開 worktree

範圍跟別人重疊、`op=start` 被擋 ⇒ **不要擠進同一個工作區**，開一份自己的：

```bash
git -C <repo> worktree add <你的路徑> -b <你的分支>   # 從最新的主線開
```

- 在自己那份裡改、在那裡 build、在那裡驗。
- 合回主線之前先核 HEAD：主線動過 ⇒ 照新 HEAD 重建產物再合，⛔ 不要拿舊底建的產物蓋掉別人的修正。
- ⛔ 不要為了進場把範圍宣告窄一點 —— 那是把撞車藏起來。
- 用完的 worktree 自己收（`git worktree remove`）。

## 5. 施工中

- 每一段做完跑 `op=status --arg status=<一句>`：順便續期（租期預設 2 小時，到期不會自動放掉，只會變殘留）。
- 動手前先 `git status`：工作區有別人的改動 ⇒ 不是你的，⛔ 不要一起 stage、一起 build。

## 6. 退場

- 綁了單 ⇒ `senate cmd commit` 推單後單子進 `in_review` 就自動收，不用記得收。
- 沒綁單、或做完了單子還沒離開施工狀態 ⇒ `op=end`。**做完就退**：宣告了產物的場掛著，別人就不能 build。
- 退場閘依每條施工路徑找工程驗編譯（.NET／Unity）：
  - 綠燈 ⇒ 退。
  - 紅燈、紅的是你範圍內的 ⇒ 修完再退。紅的不是你的 ⇒ 去問那個人，⛔ 不替別人改。
  - **找不到工程**（JS、Python…）⇒ 閘驗不了，一定紅燈。自己驗過（語法檢查、建置、測試）再
    `--arg force=1 --arg force_reason="<驗了什麼、讀數>"`。理由會落檔，⛔ 不寫「沒問題」這種沒有讀數的理由。
